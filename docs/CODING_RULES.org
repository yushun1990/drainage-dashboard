#+title: Coding Rules
* 技术栈基准
- 项目统一按 React + Vite + TypeScript 实现。
- UI 样式优先使用 Tailwind CSS。
- GIS 地图能力使用 MapLibre GL JS。
- 图表能力使用 ECharts。
- 数据来源为静态 Mock 数据，页面组件只消费整理后的结构化数据。

* React 代码规范
- 使用 React 函数组件和 Hooks，不使用类组件。
- 组件文件使用 =.tsx=，纯逻辑、配置、工具、Mock 数据文件使用 =.ts=。
- Hooks 只在组件或自定义 Hook 顶层调用，不放入条件、循环或嵌套函数。
- 自定义 Hook 使用 =use= 前缀，封装可复用状态、订阅、副作用和地图交互逻辑。
- 组件 props 使用明确类型或接口描述，复杂 props 类型优先独立声明。

* TypeScript 规范
- 禁止使用 =any=。
- 优先使用明确类型、接口、联合类型、字面量类型和泛型表达业务模型。
- 外部数据、Mock 数据和图表数据都应定义稳定的数据结构。
- 对可能为空的数据显式建模，避免依赖隐式空值假设。
- 公共类型放在独立类型文件或贴近业务模块的位置，避免在页面组件中堆积类型定义。

* 组件拆分规范
- 单个组件建议不超过 300 行。
- 页面组件只负责布局、数据组合和状态编排。
- 复杂业务逻辑拆到 hooks、utils 或独立模块。
- 可复用展示单元拆为独立组件，避免在页面文件中反复复制 JSX。
- 不在组件内堆积大型配置对象、Mock 数据或复杂计算。

* 样式规范
- 优先使用 Tailwind CSS 类名实现布局、间距、颜色和状态样式。
- 避免超长内联样式；确需动态样式时仅保留与运行时数据相关的最小字段。
- 大屏面板保持轻数字孪生 GIS 风格：半透明面板、清晰层级、信息密度适中。
- 动画用于表达状态和方向，例如异常闪烁、水流方向动画、区域高亮，不做无业务含义的装饰堆叠。
- 文本、按钮、图表和地图控件在常见大屏尺寸下不得互相遮挡。

* 地图与图表规范
- MapLibre 初始化、图层注册、事件绑定、动画和销毁逻辑应单独封装，不要堆在页面组件里。
- 地图图层、管线、站点、告警和区域高亮配置应使用明确数据结构。
- 地图副作用必须处理清理逻辑，避免重复注册事件或泄漏实例。
- ECharts 配置可拆分为独立函数或配置模块，组件只传入数据和必要参数。
- 图表颜色、单位、图例和 tooltip 文案应与业务含义一致。

* Mock 数据规范
- Mock 数据独立存放，不直接写在页面组件 JSX 中。
- Mock 文件命名体现业务含义，例如 =mockDrainageData.ts=。
- 页面组件只消费结构化 Mock 数据，不在渲染过程中临时拼装大段业务数据。
- 调整演示数据时应尽量只改 Mock 数据文件，减少对组件逻辑的影响。

* 命名规范
- React 组件使用 PascalCase，例如 =MapPipeLayer.tsx=、=AlarmPanel.tsx=。
- 自定义 Hook 使用 camelCase 且以 =use= 开头，例如 =useMapLayers.ts=。
- 工具函数和 Mock 数据文件使用 camelCase，例如 =formatFlowRate.ts=、=mockDrainageData.ts=。
- 类型和接口使用 PascalCase，例如 =DrainageAlarm=、=PipeSegment=。
- 变量命名应表达业务含义，避免无意义缩写。

* 禁止事项
- 禁止继续使用已废弃的 Vue 规范作为实现依据，包括 Composition API 和 =.vue= 组件写法。
- 禁止使用 =any= 规避类型检查。
- 禁止复制粘贴重复逻辑。
- 禁止在页面组件中堆积地图初始化、图层管理、图表大对象和 Mock 数据。
- 禁止使用魔法数字；业务阈值、颜色、尺寸和时间间隔应命名后集中管理或贴近使用场景声明。
- 禁止提交无法通过 =npm run lint= 和 =npm run build= 的代码。
